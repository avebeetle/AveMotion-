# Part25D — persistent sessions and stable authored-source ownership

Verification and measurement report, 2026-09-23. Implementation and task-scoped
independent reviews are complete. The measured2x target is **not met**; lifetime
and correctness gates pass subject to the two known Samsung baseline failures.
Final whole-stage review is pending at this report's initial commit.

## Delivered implementation

Telegram Assets retain the exact authored source used by their original metadata
Animation. Cache eviction no longer silently loses prepared source bindings.
Source-ID stamping and evaluator construction share a narrow source mutex;
recording evaluators refresh local bindings only when a published epoch changes.
The unchanged-epoch frame does not acquire that source mutex. A failed/unwinding
extraction also publishes its metadata epoch; a partial final model is never
published.

Each Instance now owns one eager recording scene session, including uncommon
huge-frame mapping. Each eligible model preparation owns one temporary recording
session for its complete ascending scan. CPU rendering remains lazy, ordinary
and independently owned. Diagnostic reset preserves already-created sessions.
There is no hidden fresh-session fallback or new production thread.

Ordinary raster/tree algorithms, canonical builders, bridge traversal, full-scene
comparator, visual goldens, feature coverage, fallback policy, Direct2D ownership
and Player threading are unchanged. Same-Instance access remains serial; tests
exercise separate Instances/Assets on host threads, not a new concurrency API.

all six intended lifetime assertions. Validator RED showed the old checker
accepting a corrupted setup-model-session count. These were functional failures,
not compile/import errors. Raw evidence is retained in `out/part25d-final/`.

frame and uses the unchanged parsed/update/finalize algorithms; expected models
are not generated by the changed Runtime. Complete model-applied scenes compare
on all16 smoke JSONs plus8 nested fixtures, both cold-source access orders and
viewport/revisit histories. Explicit model handles, live source bindings,
own-model static addresses and alias ownership prevent vacuous comparisons.

Additional checks cover all8 path/paint owners, failed partial stamping, source
eviction before/after preparation, weak ownership release, CPU isolation,
quiescent diagnostic reset, huge-frame mapping, separate-Instance/Asset stress
and same-Asset four-thread single-flight publication. A finite overflow fixture
successfully evaluates frame0, rejects frame1 with ordinary-equivalent typed
error, recovers frame0, and counts two failed model attempts as2 sessions and4
samples without publishing a partial model. Existing33 direct recording success
histories remain, with explicit error/recovery handling for the new fixture.

Test-harness corrections are recorded rather than disguised: raw bridge versus
Runtime canonical promotion was not an equivalent recovery oracle; static aliases
cannot be demanded from every animated fixture; the auto-discovery lifecycle test
needed an explicit expected-error path for the new overflow fixture. No comparator
exclusion, production promotion rule or golden was changed for these corrections.
